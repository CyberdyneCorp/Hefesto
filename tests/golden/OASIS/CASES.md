# OASIS golden test cases

Test cases to capture later. They cover the capabilities oasis-format, oasis-read, oasis-write and oasis-command. Magic has no OASIS support, so the references are of three kinds:

- **Magic GDS cross-check**: Magic 8.3.694 (commit fc5daa9e) run headless on the GDS equivalent of the input. Hefesto's OASIS result must match Magic's GDS result (oasis-read "GDS-equivalence cross-check", oasis-write "GDS-consistent content").
- **KLayout cross-check**: KLayout used as an independent converter or reader: `strm2oas`/`strm2gds`, `strmxor` (geometric XOR per layer), `strmcmp`, and the reader option `expect_strict_mode`. Use a pinned KLayout version and record it with the captures. KLayout is a reference tool only; its source is not copied.
- **Hefesto self-golden**: byte-exact files defined by the specs (native requirements). They are produced by the first conforming implementation and checked against the spec listings.

Unless stated otherwise, the technology is a minimal hand-written tech with `cifinput`/`cifoutput` styles mapping metal1 to 49/0, metal1 pins to 49/16, labels to 49/5, and metal2 to 51/0, at `scalefactor 10` (nanometer units). Comparisons of saved `.mag` files exclude `timestamp` lines. Comparisons of geometry follow decision X-1 (per-layer merged geometry, not tile order). ID ranges: 001–049 format and read, 050–089 write, 090–099 command.
