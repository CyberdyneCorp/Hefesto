# SCHEM golden test-case inventory

These cases will be captured later by running xschem `3.4.8RC` (`StefanSchippers/xschem` @ `4142e6d6f1eb5cd0e271bb183f14202af374ce27`) headless on Linux, with **gawk** installed as `awk` (see Q-SCHEM-18):
- netlists: `xschem -n -s -q --no_x -o <outdir> <file.sch>` (add `--rcfile <PDK>/libs.tech/xschem/xschemrc`; LVS mode through a `--command` or `--preinit` script setting `lvs_netlist 1`, `lvs_ignore 1` or `top_is_subckt 1`)
- round trips: `xschem --no_x -q --command "xschem load <in>; xschem saveas <out>; exit"`
- property and connectivity queries: `xschem --no_x --script <case.tcl>` printing results with `puts`

**Inputs.** Unmodified PDK example schematics at the pinned commits (`xschem_sky130` @ `2bfd7d65`, installed by open_pdks @ `c6df28c1` as `sky130A/libs.tech/xschem`; IHP `ihp-sg13g2/libs.tech/xschem` @ `5e6d592e`; gf180 `gf180mcu_fd_pr/cells/xschem` @ `5e4be872`, installed by open_pdks as `gf180mcuD/libs.tech/xschem`; all three as fetched by `scripts/fetch_pdk.py` from the ciel releases of M5 (design D17 of `openspec/changes/m8-schematic`); all Apache-2.0), and small Hefesto-authored files described inline. No file from xschem's own distribution (`xschem_library`, `tests`) is an input or is committed: xschem is GPL, and the clean-room process requires Hefesto-authored golden inputs (capability `hefesto-licensing`, Requirement "Two-team clean-room process for specs written from GPL source"; J-1 of `docs/decisions/m8-decision-table.md`). Running the xschem binary in the capture runner is allowed; its outputs are black-box behaviour. `xschem_execute_scripts` SHALL be `yes` for captures so that `tcleval` values are evaluated.

**Normalisation.** Before comparing with Hefesto output:
- xschem's driver text is dropped from `stdout.txt` and `stderr.txt` at capture (Q-SCHEM-46, approved 2026-11-25, option (b); `tools/golden/goldenlib/schem_driver.py`, applied by `capture.py` to every case of tool `xschem`), so the streams keep only what the case itself prints. Whole lines, both streams: `Created <dir> dir with template xschemrc`, `Using run time directory XSCHEM_SHAREDIR = ...`, `Sourcing <file> init file`, `setup_tcp_bespice: ...`; the lines the PDK `xschemrc` files print while sourced (`open_pdks installation: using <dir>`, `pdk installation: using <dir>`, `SKYWATER_STDCELLS:`, `SKYWATER_MODELS:`, `MODELS_NGSPICE:`, `MODELS_XYCE:`, `180MCU_MODELS:` followed by one path); the start-up errors of xschem's own Tcl files without Tk (`tclvareval(): error executing set tctx::.drw_simulate $simulate_bg: ...`, `tcleval(): evaluation of script: tk scaling failed` and its `: invalid command name "tk"` line); the `run.sh` banners `== <label>` and `== <label>: exit <n>`. On stdout only: empty lines (xschem writes one when it exits). Everything else (warnings, ERC messages, `puts` results, netlister separator lines) is kept and compared.
- replace the absolute paths in `** sch_path:` and `** sym_path:` lines by paths relative to the PDK root or test folder (Q-SCHEM-13); a path of the system symbol library becomes `$XSCHEM_SHAREDIR/xschem_library/...` (xschem's `/opt/ref/share/xschem`, Hefesto's `<CAD_ROOT>/assets/schematic`; mask `schem-paths`)
- SCHEM-NL-05 and NL-21 (sky130 `top.sch`, which places `diff_amp.sym`): an absolute path ending in `/.xschem` (the netlisting user's configuration folder in the `pre_osdi $USER_CONF_DIR/...` line) becomes `$USER_CONF_DIR` (mask `schem-user-conf`)
- SCHEM-NL-05, NL-21 and NL-23 capture the sky130 symbol generators (`sky130_tests/tier.tcl`, `res.tcl`) from an executable copy under `/work/gen/sky130A/libs.tech/xschem` that `input/run.sh` makes and `input/case.xschemrc` puts first on the library path (the read-only PDK mount keeps them non-executable); `schem-paths` reduces that copy's paths and the mount's to the same `$PDK_ROOT/sky130A/...`
- for round-trip cases, compare bytes exactly, except the `xschem version=` value when the input was written by another xschem version (Q-SCHEM-1)
- Hefesto runs with `xschem-compat` ON (the default) and "portable netlist paths" off; the OFF behaviour of the compat entries is covered by unit tests, one per mode
- flat netlists (SCHEM-NL-21) are compared by their canonical parsed form, never by bytes (Q-SCHEM-15)

**As authored (m8-schematic task 3.3).** The cases are written by `tools/golden/authoring/schem_cases.py` (see `tools/golden/README.md`, "M8: the SCHEM cases"). Choices the table leaves open: SCHEM-NL-03's testbench is sky130 `sky130_tests/gain_stage.sch`; SCHEM-NL-19 uses `tap.sym`, a Hefesto-drawn symbol of type `bus_tap`; SCHEM-NL-12, NL-13 and NL-18 build their elements from `res.sym` instances with an instance `format` or `device_model`; SCHEM-NL-17 and NL-20 set `uppercase_subckt` and `top_is_subckt` with `--tcl`; SCHEM-CMD-01's reference is xschem's netlist of `div.sch`, the circuit the divider script draws; SCHEM-SIM-01 captures the deck and SCHEM-SIM-02 the `@spice_get_*` texts with no simulation loaded, because no data set carries the PDK ngspice models; by the user decision of 2026-11-18 the simulation results are M9's and both cases are deferred to M9 (SIM-01's deck is the `dc_lv_nmos.spice` that SCHEM-NL-07 checks in M8); SCHEM-RT-05's `block.sch` places Hefesto-drawn pin and resistor symbols of the case (`block_in.sym`, `block_out.sym`, `block_res.sym`; M8 round 6), not xschem's system symbols, so the embedded block holds no xschem graphics; SCHEM-PR-05 differs from xschem in its `./` and `../` lines by the approved fix Q-SCHEM-30; SCHEM-LVS-01 extracts `sky130_fd_sc_hd__inv_1` from the `sky130` data set with Magic and compares it with netgen, using the PDK's setup file `sky130A/libs.tech/netgen/sky130A_setup.tcl` (in the `sky130-xschem` data set), against `inv_1.sch`, a Hefesto-drawn schematic of the same cell (ports A, Y, VGND, VNB, VPB, VPWR; `nfet_01v8` W=0.65, `pfet_01v8_hvt` W=1, L=0.15), so the captured result is a match (user decision 2026-11-18; it replaced `not.sch`, whose devices and ports differ from the cell's).
