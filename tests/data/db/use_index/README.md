# Use-order traces recorded from Magic

Input of INDEX's trace test (`tests/unit/db/use_index/`, m5-mask-gds-cif task 5.1, design D7; decisions Q-MASK-204 and Q-MASK-323). Each `<case>.trace` is the `trace.txt` that the golden case `tests/golden/MASK/cases/<case>/` recorded in Magic 8.3.694 (`fc5daa9e`) in the capture image. Beside it:

- `<case>.tcl` is the case's `input/commands.tcl`;
- `use_order_probe.tcl` is the probe it sources (source of truth: `tools/golden/harness/use_order/use_order_probe.tcl`).

The case inputs (technology `useorder.tech`, children `ca.mag` 4x4 and `cb.mag` 6x3, and `top.mag` for the cases that read one) are in each case's `input/`. All of these files are generated by `tools/golden/authoring/use_order_cases.py`; do not edit them by hand.

## Refreshing

1. Run `python3 tools/golden/authoring/use_order_cases.py` after a change to the probe or the cases.
2. Capture in CI. `python3 tools/golden/authoring/use_order_cases.py --dispatch` prints the `gh workflow run golden-capture.yml … -f mode=capture -f cases="…"` command. Download the `golden-expected` artifact and commit each case's `expected/`.
3. Run `python3 tools/golden/authoring/use_order_cases.py --sync`. It copies every captured `expected/trace.txt` here as `<case>.trace`. `tools/golden/tests/test_use_order_probe.py` fails when a copy differs from its capture.

## Trace format (version 1)

The format is one event per line, with fields separated by single spaces. `<n>` is the step number. It increases through the file, and all lines of one step share it. Rectangles are `xlo ylo xhi yhi` in internal units of the root `top`, and every use has an identity transform.

| Line | Meaning | Magic primitive |
|---|---|---|
| `trace 1 <case>` | header | |
| `root <cell>` | the cell whose use index is probed (`top`) | |
| `place <n> <id> <def> <rect>` | `getcell <def>` placed use `<id>` with bounding box `<rect>` | DBCellFindDup (`BPE_EQUAL`, database/DBcell.c:107, no rebuild), then BPAdd (commands/CmdFI.c:1093-1099) |
| `place <n> <id> <def> <rect> mag` | a use of `.mag` file read, in file order | BPAdd (database/DBio.c, DBPlaceCell) |
| `readmag <n> <cell> <path>` | `load <cell>` read `<path>`; its uses follow as `place … mag` lines | `load` makes no search (DBWloadWindow without `DBW_LOAD_EXPAND`) |
| `equal <n> <id> <def> <rect> rejected` | `getcell` on use `<id>`'s exact position: the copy was refused | DBCellFindDup only |
| `equal <n> <id> <def> <rect> placed <new> <rect2>` | the copy was placed after all (not expected) | as `place` |
| `search <n> <rect>` | `expand` with the box `<rect>`: one area search | DBSrCellPlaneArea, `BPE_OVERLAP` over `<rect>`, which Magic first shrinks by 1 on each side (bplane/bpEnum.c:104-106) |
| `remove <n> <id> <rect>` | `select cell <id> at <ll>` + `delete` | two `BPE_OVERLAP` searches over `[xlo, ylo, xlo+1, ylo+1]` (DBSeeTypesAll, commands/CmdRS.c; selEnumCFunc1, select/selEnum.c:650-663), then BPDelete |
| `instances <n> <def> <id>…` | `cellname list instances <def>`: the child's parent-use list (`cd_parents`) order, taken before a `resize` | none |
| `resize <n> <def> <rect>` | paint `<rect>` (child coordinates) into `<def>`, which grows its bounding box | DBReComputeBbox: every use of `<def>` is removed, then all are placed again in the `instances` order (database/DBcellbox.c:728-764) |
| `bbox <n> <id> <rect>` | the new bounding box of a use after `resize` | |
| `childinst <n> <cell> <id>…` | `cellname list childinst <cell>` | none; this is the use-id hash table order (database/DBcellname.c:524-534), *not* a use order |
| `write <n> gds\|cif <file>` | a `gds write` / `cif write` of the root | see below |
| `structures <n> gds <name>…` | the GDS structure order of that write | |
| `order <n> gds <cell> <id>…` | the SREF/AREF order in `<cell>`'s structure | `DBCellEnum` (whole plane, never rebuilds), sampled at calma/CalmaWrite.c:1486 |
| `symbols <n> cif <num>:<name>…` | the CIF symbol numbers, in definition order | numbering at cif/CIFwrite.c:333 |
| `order <n> cif <cell> <id>…` | the `C` call order in `<cell>`'s symbol | `DBCellEnum` at cif/CIFwrite.c:467 |
| `error <n> <step> <message>` | a probe step failed in Magic. The trace is then evidence of the failure, not of an order | |
| `end` | the script ran to its end. A trace without it was cut short | |

A use without an id in the written file shows as `<structure>@<x>,<y>` (GDS) or `#<symbol>` (CIF). Magic always writes the id (PROPATTR 61, CIF `91`), so neither form is expected.

### What a write searches

- MASK-UO-001..008 run with `cif *hier write disable` and `cif *array write disable`, and frame the uses with paint (`[-20, 140]` square, the uses inside `[0, 108]`). The subtree-loading search of the write (`DBCellReadArea` over the root's bounding box, calma/CalmaWrite.c:316) therefore surrounds every use, and the write makes no other search of the root's index. Each `write` line in these traces is a readout that does not change the index state. A replay checks `order` against the state that the steps before it built.
- MASK-UO-009..012 are plain writes in a fresh session, as in D7: the write's own searches (subtree loading; for GDS after the SREFs, and for CIF between numbering and calls, the CIFGenSubcells interaction searches) are part of what the trace tests. The replay must make them as INDEX's writer support does (D7 "Writers' searches and sampling points"). MASK-UO-009, 010 and 012 have uses touching the root's bounding box. MASK-UO-011 is framed, so its first write samples the unbinned order and its second shows the state that the first write's interaction searches left.
