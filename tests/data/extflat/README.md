# `.ext` files written by Magic

Inputs of EXTSUB's read tests (`tests/unit/extflat/`) and of the DEF-write net cases, from the `.ext` probe of m6-lef-def-oasis task 1.6 (Open Question 1, decided (a); design D10 and D19). Hefesto cannot extract before M7, so Magic 8.3.694 (`fc5daa9e`) writes these files in the capture image. EXTSUB only reads them; GOLDEN owns this directory.

Layout:

- `ext_probe.tcl`: the probe every target ran (source of truth: `tools/golden/harness/ext_probe/ext_probe.tcl`). It loads the target's technology and root cell, then runs `extract all` with `extract path ext`.
- `<target>/`: one directory per probe target, holding
  - `<cell>.ext`: one file per cell of the root's hierarchy, as Magic wrote it;
  - `run.tcl`: the Magic script of the run (`magic -dnull -noconsole -norc run.tcl`);
  - `probe.log`: Magic's console output of the run.
- `smoke/input/`: the smoke layout, a small committed layout that keeps the probe exercised before the LEFDEF cases exist. It is the MODEL technology `mt` with an extract style (`extsmoke.tech`), a cell `leaf` with ports `A` and `Y`, and a root `top` with two uses of `leaf`, an L-shaped wire between them (label `mid`), a top-level port `IN` and a rail through `via1` to metal2 (`vdd!`).

The targets are `smoke` and every authored DEF-write net case (LEFDEF-317..328 and 330..334; the PDK DEF cases come with task 15.5). A case's `.ext` files are also copied into its `input/`, where Magic's and Hefesto's `def write` read them. The smoke layout and the probe copy are generated by `tools/golden/authoring/lefdef_cases.py`; do not edit them by hand.

## Refreshing

1. Run `python3 tools/golden/authoring/lefdef_cases.py` after a change to the probe or the smoke layout.
2. Run the probe in CI: `gh workflow run golden-capture.yml --ref <branch> -f mode=ext-inputs` (optionally `-f cases="<case dirs>"`; `smoke` always runs). The job summary lists every target and the cases skipped because they are not authored yet.
3. Download the `ext-inputs` artifact and run `python3 tools/golden/authoring/lefdef_cases.py --sync-ext <artifact dir>`. It refuses a target whose run did not finish, printed an error, left feedback, or wrote an incomplete `.ext` file (`tools/golden/goldenlib/extfile.py`), and copies the others here and into the cases' `input/`.
