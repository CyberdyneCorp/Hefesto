# Diagnostic codes: drc area

Codes `DRC-<TOPIC>-<NNN>` emitted by `src/core/src/drc/` (design rule
checking; `openspec/changes/m3-drc/design.md` D1/D2). Conventions and the
renderings are described in [../codes.md](../codes.md).

The area's table is assembled by `src/core/src/drc/codes.cpp` (owner:
INTEGRATION) from one fragment per workstream, each owned by that
workstream and sorted by code:

| Fragment | Topics | Owner |
|---|---|---|
| `src/core/src/drc/check/codes.inc` | `DRC-CHECK-*` | CHECK |
| `src/core/src/drc/commands/codes.inc` | `DRC-CMD-*` | COMMANDS |
| `src/core/src/drc/engine/codes.inc` | `DRC-ENG-*` | ENGINE |
| `src/core/src/drc/rules/codes.inc` | `DRC-LINT-*`, `DRC-TECH-*` | RULES |

`DRC-LINT-*` warnings are native-only diagnostics (`diag::make_native`):
`--diagnostics=magic` drops them, so golden console captures stay identical
to Magic's, while `text` and `json` print them (design D4).

The table below is generated from the fragments:

```sh
hefesto-cli --diagnostic-codes=drc
```

The unit test `each area's code table matches its document and prefix`
fails when the two disagree.

## RULES

Rule compiler, rule table and cifoutput catalog (`drc-rule-language`,
`tech drc`; `src/core/src/drc/rules/`, a port of `drc/DRCtech.c`,
`drc/DRCcif.c` and `drc/DRCprint.c`).

- **`DRC-TECH-001`, `DRC-TECH-002`.** Every `TechError` of the drc section
  keeps Magic's text and the `TechPrintLine` location (`<file>: line <n>:
  section drc:` in the `magic` rendering). Messages that start with
  `Warning` (and the `surround_ok` advice) are warnings; the others are
  errors. None of them fails the technology load. Type-name errors in rule
  lines are `TECH-LINE-*` (the shared type-list parser); like Magic, the
  plow rule reader repeats them for `edge`, `edge4way`, `spacing` and
  `width` lines of every style.
- **`DRC-TECH-003`.** `drc style <name>`: `DRC style "<name>" is
  ambiguous.` or `"<name>" is not one of the DRC styles Magic knows.` (the
  `drc` command then prints the style list); also an unknown cifoutput
  style name in `drc::CifCatalog::select`.
- **`DRC-TECH-004`.** `DRC style is now "<name>"` (informational).
- **`DRC-TECH-005`.** `tech drc surr|direc <layer>` without the second
  layer: `Requires two layer types.` An unknown layer in `tech drc` is
  `TECH-CMD-006` (`No such layer <n>`); `TECH-CMD-005` is retired.
- **`DRC-TECH-006`.** `Loading DRC CIF style.` (drcCifCheck): the first
  check after a style whose `cifstyle` names a cifoutput style that is not
  current selects that style and reloads the DRC style
  (`drc::after_basic_check`); the mask-layer checks themselves are M5.
- **`DRC-LINT-001`** (Q-DRC-3). A `spacing` rule whose type lists span
  several planes: Magic compiles only the first plane pair. The warning
  names the dropped pairs in both `magic-compat` modes; with it OFF they
  are compiled.
- **`DRC-LINT-002`** (Q-DRC-18). `surround ... exact_width` where an inside
  and an outside type share no plane: only the absence rules exist there,
  in both modes.
- **`DRC-LINT-003`** (Q-DRC-19). `maxwidth` exclude types with
  `bend_illegal` or `both`: they are ignored, in both modes.

The three `DRC-LINT-*` warnings are native only: `--diagnostics=magic`
drops them.

## CHECK

Basic check kernel (`drc-rule-semantics`). The kernel reports DRC errors
through `drc::ErrorSink`, not as diagnostics; codes here are for kernel
failures only.

M3 defines no `DRC-CHECK-*` code. The kernel cannot fail: a missing rule
set or a null check area reports nothing, a rule whose check plane does not
exist in the cell is ignored, and a cancelled check (background worker)
returns `CheckOutcome::cancelled` for the engine to retry, not a diagnostic.

## ENGINE

Check and error planes, marking, step squares, hierarchy and the background
checker (`drc-engine`).

- `DRC-ENG-001` (`drc check`): a cell of the subtree under the area could
  not be read (`DBCellReadArea`); the text is Magic's two lines
  `Failure to read in entire subtree of cell.` and `Failed on cell <name>.`
  and nothing is marked.

The engine reports DRC errors into the error planes, not as diagnostics.

Hefesto does the same.

## COMMANDS

The `drc` command (`drc-commands`): a port of `CmdDrc`
(`commands/CmdCD.c`) and the reporting of `drc/DRCmain.c`. Its console
text keeps Magic's wording; the results of `list`/`listall` are
`cmd::Value` lists with Magic's Tcl structure.

- `DRC-CMD-001` carries every line Magic prints with `TxPrintf`: help,
  `drc why` texts, `Error area #N:`, the `drc count` lines, the `*halo`
  and `*stepsize` reports, `drc statistics`, `drc printrules` output.
  `There aren't that many errors` is printed by Magic without a newline;
  Hefesto emits it as one line.
- `DRC-CMD-002` carries the `TxError` lines: `No option given in ":drc"
  command.`, `<arg> isn't a valid drc option.`, the three-line
  wrong-arguments text, `Cannot write file <file>`. The command still
  succeeds, as in Magic.
- Errors of the engine (`drc check` reading the hierarchy) and of the
  style selection (`drc style <name>`) are reported with the owner's code
  (`DRC-ENG-*`, `DRC-TECH-*`) and the command still succeeds.
