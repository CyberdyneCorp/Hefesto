# Diagnostic codes: undo area

Codes `UNDO-<TOPIC>-<NNN>` emitted by `src/core/src/undo/` (owner: UNDO,
`openspec/changes/m2-interactive-editing/design.md` D1/D2). Conventions and
the renderings are described in [../codes.md](../codes.md).

The table below is generated from `src/core/src/undo/codes.cpp`:

```sh
hefesto-cli --diagnostic-codes=undo
```

The unit test `each area's code table matches its document and prefix`
fails when the two disagree.

The `undo` and `redo` commands report Magic's console lines with these
codes: `Nothing more to undo`/`redo` and the `print` listings are
`UNDO-REPORT-001`; Magic's error lines (usage texts, `Count must be a
positive integer`, `Option must be a count (integer)`, `Count must be
numeric`) are `UNDO-CMD-001` failures; `undo` while recording is disabled
warns with `UNDO-CMD-002` and then reports `Nothing more to undo`.

<!-- BEGIN DIAGNOSTIC CODES (generated by `hefesto-cli --diagnostic-codes=undo`) -->
| Code | Default severity | Meaning |
|---|---|---|
| `UNDO-CMD-001` | error | Invalid undo or redo arguments (usage, or a count that is not a positive integer). |
| `UNDO-CMD-002` | warning | Undo was attempted while undo recording is disabled; nothing was undone. |
| `UNDO-LIMIT-001` | error | The undo history limit must be an integer of at least 1000; the previous limit is kept. |
| `UNDO-REPORT-001` | info | A report the undo or redo command prints (Magic's TxPrintf text). |
