# Diagnostic codes: netlist area

Codes `NETLIST-<TOPIC>-<NNN>` emitted by `src/core/src/netlist/` (the layout netlisters: `ext2spice`, `ext2sim` and `extcheck`; capabilities netlist-spice-options, netlist-spice-devices, netlist-spice-hierarchy, netlist-sim and netlist-extcheck;
`openspec/changes/m7-extraction/design.md` D2/D3). Conventions and the renderings are described in
[../codes.md](../codes.md).

The area's table is assembled by `src/core/src/netlist/codes.cpp` (owner:
INTEGRATION) from one fragment per workstream, each owned by that
workstream. The rows are sorted while compiling
(`src/core/src/diag/sorted_codes.hpp`):

| Fragment | Topics | Owner |
|---|---|---|
| `src/core/src/netlist/spice/codes.inc` | `NETLIST-SPICE-*` | SPICE |
| `src/core/src/netlist/sim/codes.inc` | `NETLIST-SIM-*` | SIM |
| `src/core/src/netlist/extcheck/codes.inc` | `NETLIST-CHECK-*` | SIM |

The shared files `netlist/first_word.cpp` (the first-word rule of Q-NETLIST-13) and `netlist/table_command.cpp` (the dispatcher shape of `ext2spice`, `ext2sim` and `antennacheck`) are INTEGRATION's and report no code.

The M7 scaffold (tasks.md 3.2, 3.3) declared no code. While M7 is in
progress, a command option or function the scaffold declared before its
workstream implemented it fails with the core code `CORE-NOTIMPL-008`
([../codes.md](../codes.md)); INTEGRATION retires it at M7 exit.

## SPICE

Codes of the SPICE netlister (`ext2spice`, `exttospice`). Owner: SPICE. None yet.

## SIM

Codes of the sim netlister (`ext2sim`, `exttosim`). Owner: SIM.

- `NETLIST-SIM-001` carries the lines Magic prints with TxPrintf during a
  run: `Devices merged: <n>` after the merge pre-pass, `Cap accuracy option
  -y is deprecated.` and `exttosim finished.`.
- `NETLIST-SIM-002` carries the lines Magic prints with TxError: a run flag
  without its value or not recognised (followed by the usage text), `Point
  to a window or specify a cell name.`, the SU-format warning that the
  extraction style does not match the `.ext` file, and the `.sim`-format
  errors of the device writer (a FET type that starts with neither `n` nor
  `p`, a missing substrate area class). The option handlers' messages
  (`exttosim: output formats are MIT, LBL, or SU`, ...) are the shared
  command messages of `db/command_util.hpp`.
- `NETLIST-SIM-003` is a failed write of `<cell>.sim`, `.al` or `.nodes`;
  the run fails. Each run writes only its own files (Q-NETLIST-52).

## CHECK

Codes of `extcheck` and `hefesto-extcheck`. Owner: SIM. None: `extcheck`
is a standalone program that prints Magic's text on its output and error
streams and reports through its exit status (0, or 1 after the usage text
or a failed read). A failed read prints the extflat diagnostic as
`<argv[0]>: <code> <text>` on the error stream (design D15).
