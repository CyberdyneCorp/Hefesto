# Diagnostic codes: route area

Codes `ROUTE-<TOPIC>-<NNN>` emitted by `src/core/src/route/` (the maze
router: the technology `mzrouter` section and styles, the maze engine,
`iroute` and the `*iroute` / `*mzroute` diagnostics; capabilities
router-maze and router-maze-iroute; `openspec/changes/m10-plot-route/design.md`
D3). Conventions and the renderings are described in
[../codes.md](../codes.md).

The area's table is assembled by `src/core/src/route/codes.cpp` (owner:
SCAFFOLD) from one fragment per workstream, each owned by that workstream.
The rows are sorted while compiling (`src/core/src/diag/sorted_codes.hpp`):

| Fragment | Topics | Owner |
|---|---|---|
| `src/core/src/route/tech/codes.inc` | `ROUTE-TECH-*` | MZTECH |
| `src/core/src/route/maze/codes.inc` | `ROUTE-MZ-*` | MZ |
| `src/core/src/route/iroute/codes.inc` | `ROUTE-IROUTE-*` | IROUTE |
| `src/core/src/route/diag/codes.inc` | `ROUTE-DIAG-*` | IROUTE |

The scaffold (tasks.md 3.1) declared no code. Until a workstream lands its
part, `iroute`, `*iroute`, `*mzroute` and the area-contract functions
report `CORE-NOTIMPL-010` ([../codes.md](../codes.md)).

## MZTECH

Codes of the technology `mzrouter` section reader, the style derivation
from DRC and the derived `irouter` style (`route/tech/`; "mzrouter section
grammar", "Style defaults and lookup", "Width and spacing derivation from
DRC", "Derived irouter style"). Every message is Magic's text from
`mzrouter/mzTech.c` (the same in both `magic-compat` settings), printed
with the technology line context (TechError) except the two penalty codes,
which Magic prints with TxError. A statement that reports any of them
defines nothing, in both settings (Q-LEGACY-31, -39, -47); unknown type
names are reported by the technology reader's own type-name codes.

| Code | Messages |
|---|---|
| `ROUTE-TECH-001` | `Missing style line.` |
| `ROUTE-TECH-002` | `"style" lines need a style name` (Hefesto: Magic copies a missing name; Q-LEGACY-39) |
| `ROUTE-TECH-003` | `Unrecognized keyword: "<keyword>"` |
| `ROUTE-TECH-004` | `Malformed "layer" line, should be:  "layer name hCost vCost [jogCost [hintCost [overCost]]]"`, `Attempt to define two route layers on same plane:  <type> and <type>`, `Type "<name>" appears on more than one plane`, `Cost arguments to "layer" line must be numeric`, `<hCost\|vCost\|jogCost\|hintCost\|overCost> must be > 0` |
| `ROUTE-TECH-005` | `Malformed "contact" line, should be:  contact layer layer1 layer2 cost`, `route layer must be declared before used in contact.`, `Cost argument to "contact" line must be numeric`, `Cost must be > 0` |
| `ROUTE-TECH-006` | `Bad form on mzroute notactive.` + `Usage: notactive routeType1 ... [routeTypen]`, `Unrecognized route type: "<name>"` |
| `ROUTE-TECH-007` | `Bad form on mzroute spacing.` + `Usage: spacing routeType type1 spacing1 ... [typen spacingn]`, `Unrecognized route type: "<name>"`, `Unrecognized layer (type): "<name>"`, `Bad spacing value: <v>` + `Valid values are nonnegative integers and "NIL".` |
| `ROUTE-TECH-008` | `Bad form on search.` + `Usage: search <rate> <width> <penalty>`, `Bad rate: <v>` + `Rate must be a positive integer.`, `Bad width: <v>` + `Width must be a positive integer.` |
| `ROUTE-TECH-009` | `Bad penalty value: <v>` + `Penalty must be non-negative decimal.` |
| `ROUTE-TECH-010` | `Penalty value out of range: <v>` (Hefesto, both settings: the stored mantissa floor(p × 2) does not fit in 32 bits; Q-LEGACY-47) |
| `ROUTE-TECH-011` | `Bad form on mzroute width.` + `Usage: width <routeType> <width> [<length>]`, `Unrecognized route type: "<name>"`, `Bad width: <v>` + `Width must be a positive integer.`, `Bad minimum length: <v>` + `Length must be a positive integer.` |

## MZ

Codes of the maze engine (`route/maze/`; the other router-maze
requirements). None yet.

## IROUTE

Codes of `iroute`, its parameters, `saveParameters` and endpoints
(`route/iroute/`), and of the `*iroute` and `*mzroute` diagnostics
(`route/diag/`; the router-maze-iroute requirements). None yet.
