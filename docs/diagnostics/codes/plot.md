# Diagnostic codes: plot area

Codes `PLOT-<TOPIC>-<NNN>` emitted by `src/core/src/plot/` (the `plot`
command: the technology `plot` section, the plot parameters, the plotted
region, atomic output files, the PostScript and PNM writers; capability
plot-output; `openspec/changes/m10-plot-route/design.md` D3).
Conventions and the renderings are described in [../codes.md](../codes.md).

The area's table is assembled by `src/core/src/plot/codes.cpp` (owner:
SCAFFOLD) from one fragment per workstream, each owned by that workstream.
The rows are sorted while compiling (`src/core/src/diag/sorted_codes.hpp`):

| Fragment | Topics | Owner |
|---|---|---|
| `src/core/src/plot/tech/codes.inc` | `PLOT-TECH-*` | PLOTTECH |
| `src/core/src/plot/params/codes.inc` | `PLOT-PARAM-*` | PLOTCMD |
| `src/core/src/plot/cmd/codes.inc` | `PLOT-CMD-*` | PLOTCMD |
| `src/core/src/plot/io/codes.inc` | `PLOT-IO-*` | PLOTCMD |
| `src/core/src/plot/ps/codes.inc` | `PLOT-PS-*` | PS |
| `src/core/src/plot/pnm/codes.inc` | `PLOT-PNM-*` | PNM |

The view export (`display/export/`, owner EXPORT) is part of the display
area: its codes are `DISPLAY-EXPORT-*` in [display.md](display.md).

The scaffold (tasks.md 3.1) declared no code; PLOTTECH (tasks 4.1, 4.2)
adds the TECH codes below. Until a workstream lands its
part, the `plot` command and the area-contract functions report
`CORE-NOTIMPL-010` ([../codes.md](../codes.md)).

## PLOTTECH

Codes of the technology `plot` section reader (`plot/tech/`; "Technology
plot section structure", "PostScript style lines", "PNM style lines",
"Raster printer and legacy plot devices"). Every message is Magic's text
and never fails the load. Those Magic reports with `TechError` carry the
line and the section (the Magic rendering prints `<file>: line <n>: section
plot:` first); those Magic reports with `TxError` (005, 006) have no
location.

- `PLOT-TECH-001`: `"style" lines must have exactly two arguments` (the
  current style is kept), `Plot style "<name>" doesn't exist.  Ignoring.`
  and `Must declare a plot style before anything else.` (lines are skipped
  until the next `style`).
- `PLOT-TECH-002`: `"ps" lines must have either 9, 5, or 3 arguments.`
- `PLOT-TECH-003`: `2nd field must be an integer`, `3rd field must be an
  integer or "S", "X", or "B".`, and, fixed in both modes (Q-MISC-50 (2);
  Magic keeps an indeterminate value), `"ps" line field "<f>" is not an
  integer` for a pattern or colour line whose index, colour component or
  hexadecimal row does not start with a number.
- `PLOT-TECH-004`: `"map" lines need at least one type`, a bare `map`
  line, fixed in both modes (Q-MISC-50 (1); Magic dereferences a missing
  argument).
- `PLOT-TECH-005`: `Couldn't open colormap file "<file>"`, `Format error in
  colormap file`, `PNM plot: Could not open display style file` and
  `Format error in display style file`. The technology still loads; `plot
  pnm` refuses with Magic's "PNM module initialization had failed" until
  the next load (`PlotTech::init_failed`, Magic's `Init_Error`).
- `PLOT-TECH-006`: `Unknown drawing style "<s>" for PNM plot.` (only when
  no plot dstyle file is loaded, as Magic) and `Unknown magic layer "<t>"
  for PNM plot.` of a three-field `draw` line.

Unknown type names in a `postscript` layer line are reported by the
technology reader's `Unrecognized layer (type) name "<name>"`
(`TECH-LINE-002`, [tech.md](tech.md)) and the line is kept, as Magic's
`DBTechNoisyNameMask`. The `versatec`, `colorversatec`, `gremlin` and
`pixels` blocks report nothing (Q-MISC-51 (a)).

## PLOTCMD

Codes of the `plot` command, the plot parameters, the plotted region and
the atomic output files (`plot/cmd/`, `plot/params/`, `plot/io/`; "Plot
command and plotted region", "Plot parameters", "Plot output safety and
limits"). None yet.

## PS

Codes of the PostScript writer (`plot/ps/`; the "PostScript ..."
requirements). None yet.

## PNM

Codes of the PNM writer (`plot/pnm/`; "PNM rasterisation and file format",
"Platform mechanism of plot output"). None yet.

## EXPORT

The SVG and PNG view export reports `DISPLAY-EXPORT-*` codes
([display.md](display.md)); `plot svg` reports them through `plot`. None
yet.

hefesto-cli --diagnostic-codes=plot
