# Audit G2: cmd-*, drc-*, mask-*, GDS/CIF/OASIS, antenna, font labels

Scope: antenna-check cif-format-io cmd-box cmd-coordinates-and-units cmd-hierarchy cmd-labels-properties cmd-misc-edit cmd-paint-erase cmd-selection drc-cif-rules drc-commands drc-engine drc-rule-language drc-rule-semantics font-labels gds-read gds-write mask-hierarchical-generation mask-hints mask-input-styles mask-output-operators mask-output-styles oasis-command oasis-format oasis-read oasis-write.

Method:
- Mechanical checks over all 26 specs: Compatibility line, trace line, scenario, SHALL in the first sentence, Magic C names, capability references, Q-IDs, and requirement-name references.
- Pairwise reading of overlapping requirements, with Magic source checked at fc5daa9e. The checkout is at 9c83a9a6, which has no `.c`/`.h` changes since fc5daa9e.

Result: no dangling Q-IDs or capability names. Every spec passes `openspec validate --type spec --strict`, before and after the edits.

## Fixed

1. **cmd-selection** — "Floating selection (pick, move, keep)": the first sentence used MAY, with no SHALL. It now opens with "Hefesto SHALL support a floating selection: …". Reason: convention rule 2.1.
2. **mask-output-operators** — "Non-Manhattan merge option" is now a reference to `mask-hierarchical-generation` "Non-manhattan merge option". I also replaced the wrong scenario. The old text said `cif unfracture yes` sets the switch and `cif unfracture` queries it. In Magic, the value is the 4th word, `cif unfracture <x>` queries, and `cif unfracture` alone is an argument error (CmdCD.c:2066-2080, Q-MASK-413).
3. **cif-format-io** — "cif polygon and unfracture options": now describes the unfracture argument form correctly, with Q-MASK-413 and the Magic ref range widened to 2014-2080. Reason: it contradicted mask-hierarchical-generation and Magic.
4. **cif-format-io** — "CIF output preconditions and flat output": the flat-output paragraph is now a reference to `mask-hierarchical-generation` "Flat CIF output", which owns it. Reason: duplicate.
5. **mask-hints** — "Mask hints from cifinput templayers" described the fixed behaviour (union) as if it were Magic's, and its scenario said "adds to the existing region". Magic replaces the region: the lookup key is the bare `<name>` (CIFrdcl.c:736-753). Text and scenario now state Magic's behaviour and cite Q-MISC-11 and Q-MASK-308. Reason: rule 7 (never silently fix), and a contradiction with mask-input-styles.
6. **mask-hints** — Purpose now states the ownership explicitly: data model, both creation paths, and the output operator semantics. The other capabilities refer here.
7. **mask-input-styles** — "Input operator mask-hints" is reduced to a reference to `mask-hints`. The wrong Magic ref CIFrdcl.c:426-520 is corrected to 700-800.
8. **gds-read** — Purpose and "Mask hints on input": the ownership pointer was `mask-output-operators`. It is now `mask-hints`, and `mask-hints` governs if the texts differ.
9. **mask-output-operators** — the `mask-hints` entry now refers to `mask-hints` "Mask-hint output operator" for the full semantics.
10. **mask-output-styles** — "Interaction radius" duplicated `mask-hierarchical-generation` "Halo radius", including Magic `if/else` wording. It is reduced to the formula plus a reference. The scenario is kept, and it is consistent.
11. **drc-commands** — "Scripting results on iPadOS and non-Tcl hosts" said "even where Tcl is unavailable". That contradicts X-3, which puts Tcl everywhere, including iPadOS. It now refers to `scripting-api` and X-3.
12. **font-labels** — "Font-related label commands": the setlabel size/offset/rotate bullet duplicated `cmd-labels-properties`. It is now a reference, citing Q-MISC-23 and Q-CMDEDIT-90.
13. **font-labels** — "GDS representation of font attributes" re-specified the PRESENTATION/MAG/ANGLE formulas owned by `gds-write` "Label TEXT records" and `gds-read` "TEXT element parsing". It is now a summary with references. The font-not-loaded fallback is kept.
14. **antenna-check** — "Shared antenna definitions for LEF output" re-specified the LEF per-pin computation. It now refers to `lef-write` "Antenna areas" and keeps only the definitions of the shared G and D sets.
15. **cmd-hierarchy** — "Archive command" contradicted `cell-io-safety` "Archive files" and Magic (CmdAB.c:84-147, DBio.c:6382-6560):
    - It said `write` writes only modified cells. Magic writes all available non-internal/not-found/read-only cells.
    - It had the `read` vs `readref` dereference semantics reversed.
    - It cited the wrong owning capability (`cell-file-format`).
    - Its scenario `archive read arch.mag` would open `arch.mag.mag` (Q-CELL-34).
    I corrected all four and added the reference.
16. **cmd-hierarchy** — "Locking mechanism" duplicated `cell-io-safety` "Locking mechanism", and put a SHALL inside an informative requirement. It is now a reference, citing Q-CELL-26 and Q-CMDEDIT-33.
17. **cmd-hierarchy** — "Cell and instance naming rules": the generated-identifier paragraph now refers to the owner, `layout-hierarchy` "Instance identifier assignment".
18. **cmd-misc-edit** — "Feedback command" said 4 values make a rectangle. Magic and `ui-feedback-and-highlights` say 2 points make a line (CmdFI.c:260-288). It also omitted the default style `pale`. I fixed both, made the text a summary that refers to the owner, and noted this in Purpose.
19. **cmd-coordinates-and-units** — "Scalegrid command" now states that `tech-loading-and-scaling` "scalegrid command" governs the rescaling, which includes the unscaled infinity markers. "Keyword matching" now refers to `ui-command-dispatch` "Command name lookup", which is the same algorithm.
20. **cmd-box** — "Box tool pointer gestures" said the touch gestures were an undecided UI matter. They now follow X-5 (decided), with Q-CMDEDIT-13 kept for the remaining details.
21. **docs/decisions/open-questions/MASK.md** — Q-MASK-308 evidence was CIFrdcl.c:454-473, which has no hint code. Corrected to 736-753.
22. **docs/decisions/open-questions/CMDEDIT.md** — Q-CMDEDIT-34 evidence was CmdAB.c:150-190. Corrected to 118-145.

## Cross-group findings

- **docs/decisions/open-questions MISC.md and MASK.md** — Q-MISC-11 and Q-MASK-308 are the same bug (templayer hint lookup key). Merge them into one, keeping the other as a pointer.
- **MISC.md and CMDEDIT.md** — Q-MISC-23 and Q-CMDEDIT-90 overlap (the `setlabel offset` query prints x twice). Merge them.
- **CMDEDIT.md and CELL.md** — Q-CMDEDIT-33 duplicates Q-CELL-26 (locking platform), and Q-CMDEDIT-35 duplicates Q-CELL-30 (crash-backup location). Merge them into the CELL entries, which are more detailed.
- **CMDEDIT.md** — Q-CMDEDIT-34 says "uninitialised option". In fact `option = -1`, so the switch is a no-op, and the impact is cosmetic. Re-word it.
- **DRC.md** — Q-DRC-12 still says "iPadOS has no Tcl". Update it for X-3: Tcl is embedded everywhere, so only the scheduling part stays open.
- **CMDEDIT.md** — Q-CMDEDIT-96 (`shell` without process spawning) is answered by P-13 and the `hefesto-ipad-feature-scope` desktop-only list. Mark it resolved.
- **ui-tools-and-input** — "Box tool buttons" points to `paint cursor` in `cmd-box`. It should point to `cmd-paint-erase`. The requirement otherwise duplicates `cmd-box` "Box tool pointer gestures", consistently. Pick one owner: suggest `cmd-box` for the semantics and `ui-tools-and-input` for cursor glyphs only.
- **tech-loading-and-scaling vs cmd-coordinates-and-units** — the `scalegrid` command is fully specified twice. The two are consistent today, and cmd-coordinates now defers on the rescaling. Suggest that tech-loading keep only the rescale procedure and drop the command syntax and usage text.
- **ui-command-dispatch "Command name lookup" vs cmd-coordinates-and-units "Keyword matching"** — the same lookup is classed `exact` in one and `behavioral` in the other. Align the classes.
- **cell-io-safety** — no change needed. It is now the referenced owner for archive and locking.

## Needs decision

- **Mask-hint ownership split.** I assigned all hint semantics to `mask-hints`, following its Purpose. `mask-output-operators` and `mask-input-styles` keep catalog entries. Confirm this, or move the operator semantics back to `mask-output-operators`.
- **Q-MISC-11 / Q-MASK-308 resolution (X-2 tier).** Is templayer hint replacement a data-loss bug, so always fixed (tier 1), or a compat quirk? Both entries recommend "fix". The spec currently states Magic's behaviour.
- **Q-MASK-413 (`cif unfracture` 4th word).** The entry recommends "accept both forms". Under X-2 this needs a `Resolution:` line: compat-flag or always accept.
- **`cmd-hierarchy` "Archive command" stops after a usage error (Q-CMDEDIT-34).** Behaviour is observably the same as Magic's. Record the resolution as `fix`.
- **OASIS requirements mix traces** of the form `(Hefesto decision: P-6; Magic ref: …)` on `exact`/`behavioral` requirements. This is outside the letter of convention rule 3, but it is sensible. Either bless it in docs/spec-conventions.md or split the traces.
- **`drc-rule-semantics` pseudo-code** uses `TopType`/`LeftType`/`RightType`, which mirror Magic tile macros. They are defined in the Conventions paragraph, so I left them. Decide whether to rename them (`topType(...)`) for implementation independence. The same question applies to the set names `HierLayers`/`YankTypes`/`NonlocalGen` in mask-hierarchical-generation.
