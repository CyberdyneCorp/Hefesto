# Spec audit — group G4

Scope: `lvs-command`, `lvs-comparison-algorithm`, `lvs-device-reduction`, `lvs-hierarchy`, `lvs-netlist-input`, `lvs-property-matching`, `lvs-reports`, `lvs-setup-file`, `schematic-command`, `schematic-editing`, `schematic-file-format`, `schematic-netlisting`, `schematic-simulation-integration`, `schematic-symbols-and-libraries`, `simulation-analyses-and-results`, `simulation-command`, `simulation-corners`, `simulation-engine-embedding`, `simulation-measurements-and-statistics`, `simulation-monte-carlo`, `simulation-netlist-preparation`, `simulation-optimization-hooks`, `simulation-sweeps`, `simulation-ui-and-crossprobe`. Open-question files: `SIM.md`, `SIMADV.md`, `SCHEM.md`, `LVS.md`.

Checks run:
- Every requirement has exactly one Compatibility line, a trace (`Magic`/`netgen`/`xschem`/`ngspice ref` or `Hefesto decision`), and at least one scenario. All requirements passed.
- Every Q-ID, decision ID, capability name and `Requirement "…"` cross-reference resolves, both from these specs and into them from other specs. Two dangling references were found and fixed.
- Contradictions within and between specs, and with decisions X-1…X-6, P-5, P-7, P-12, P-13 and P-19.
- `openspec validate <cap> --type spec --strict` passes for all 24 specs after the edits.
- The ngspice seeding behavior was verified in the read-only clone at the scratchpad path, `src/src/...`.

## Fixed

1. **`simulation-engine-embedding`, "Deterministic engine initialisation" (Q-SIMADV-7).**
   - Removed `set rndseed=1` from the fixed command list. In ngspice it only sets a variable. `ngSpice_Init` seeds the generator from `getpid()` (`sharedspice.c:930-951`, `randnumb.c:303-330`).
   - The adapter now sends `setseed <s>` after the PDK initialisation commands, before every deck load. `s` is 1 for ordinary jobs and `s_i` for Monte Carlo samples.
   - Verified: `setseed` calls `srand`, then `TausSeed`, then `initw`. `initw` sets up the Wallace pool that `trnoise` uses, so `trnoise` and `trrandom` sources are covered (`randnumb.c:292-330`, `trannoise/wallace.c:76`).
   - The scenario "Reproducible random sources" now checks a `trnoise` source and an `agauss` parameter across two fresh engines with different process ids.
2. **`simulation-engine-embedding`, "OSDI compact models" (Q-SIMADV-5).** The built-in sg13g2 set is now the six modules that the sg13g2 `.spiceinit` loads. This adds `cap_cmomi` and `cap_cmomf`.
3. **`simulation-engine-embedding`, "ngspice build configuration and license hygiene" (Q-SIMADV-6).**
   - The build manifest SHALL list the Hefesto ngspice patches: static OSDI registry, static code models and portable seeding. `simulation-monte-carlo` assumed this requirement already existed.
   - Added a scenario.
4. **`simulation-engine-embedding`, traceability.** Q-SIM-1, Q-SIM-7, Q-SIM-12, Q-SIM-15 and Q-SIM-19 were not cited by any spec. They are now linked from the requirements they concern.
5. **`simulation-command` (Q-SIMADV-1).**
   - The subcommand table now lists `corners`, `sweep`/`doe`/`runset`, `mc`, `meas`/`spec`/`stats` and `opt`. Their syntax is delegated to the owning capabilities, so it is not duplicated. The usage error takes its syntax from the owning capability.
   - `corner sweep` is defined as creating an unnamed user corner set.
   - `run -all` starts a run set whose only dimension is the corner set.
   - Added a scenario for `sim help`.
6. **`simulation-command`, option matching.** The new options created real ambiguities, because some option names are prefixes of others:

   | Exact name | Longer name |
   |---|---|
   | `corner` | `corners` |
   | `meas` | `measure` |
   | `opt` | `option` |
   | `run` | `runset` |
   | `stat` | `stats`, `status` |

   Changes:
   - Added the rule from Magic's keyword lookup that an exact whole name wins. `vector`/`vectors` already needed this rule.
   - The scenario "`sim stat` acts as `sim status`" became false and was replaced by `sim statu`.
   - The ambiguous-prefix scenario now uses `stat`.
   - Added a scenario for the exact-name rule.
7. **`simulation-netlist-preparation`, descriptor (Q-SIMADV-2, Q-SIMADV-5).**
   - The sky130 model root is now `libs.tech/combined`. This matches `simulation-corners`, `simulation-monte-carlo` and the `schematic-simulation-integration` scenario. Before, the deck example and two scenarios used `libs.tech/ngspice`.
   - The sg13g2 OSDI column now lists all six modules.
   - Row labels are now `sky130A/B` and `gf180mcuC/D`, as the text says.
   - The requirement now names `simulation-corners` ("Bundled corner tables") as the owner of the full corner tables, the extra section variables (`<dio>`, `<moscap>`) and the rule that a model line is emitted only when its file is used. Before, the two specs disagreed on which model lines are emitted.
8. **`simulation-netlist-preparation`, "Corners".** The requirement now says that a corner sweep runs as the corner dimension of a run set.
9. **`simulation-netlist-preparation`, "Deck validation and sanitisation".** The schematic-deck exemption named only `write` and `quit`. The translation table of `schematic-simulation-integration` also maps `wrdata` and removes `exit`. The text now lists all four. The scenario now says `quit` is removed.
10. **`simulation-netlist-preparation`, dangling reference.** `Requirement "Schematic as a circuit source"` is now `"Schematic circuit source"`.
11. **`simulation-analyses-and-results` and `simulation-sweeps`, contradictory job ids and folders.**
    - `simulation-analyses-and-results` required every job id to be `<date>-<time>-<tb>-<corner>` and every job folder to be `simulations/<tb>/<job-id>/`. Run-set point jobs use `<run set id>-p<index>` and `…/<run set id>/p<index>/`. Both rules are now stated, with `simulation-sweeps` as the owner.
    - In `simulation-sweeps`, `p<index>/` existed only for points whose waveforms were kept, yet every point SHALL keep `job.json` and `log.txt`. Now every point that ran has a `p<index>/` folder, and only `result.raw` follows the retention setting.
12. **`schematic-symbols-and-libraries`, dangling reference.** `schematic-netlisting` Requirement "Attribute substitution" is now "Format string substitution".
13. **`schematic-command`, "Headless use".**
    - `hefesto --netlist` is now `hefesto-cli --netlist`. `hefesto-cli` is the headless executable used by every other spec.
    - `--lvs` is defined as turning on options `lvs_netlist` and `lvs_ignore`, which is the PDK LVS convention.
14. **`schematic-simulation-integration`, "Schematic-driven LVS command".**
    - The text you can retrieve is now `schematic netlist -lvs -lvsignore`. The LVS run uses `lvs_ignore` on, so `-lvs` alone would give different text.
    - The scenario `lvs inv.mag inv.sch sky130A` could not work: `.mag` fails format detection in `lvs-netlist-input`. It now reads `lvs -layout inv inv.sch sky130A`.
15. **`lvs-command`, "Layout netlist from extraction".**
    - The schematic side said only "any file accepted by `lvs-netlist-input`", which has no `.sch` reader. A `.sch` name, in either the netgen form or the layout form, is now netlisted in memory in LVS mode, delegating to `schematic-simulation-integration`.
    - The `ext2spice lvs` preset now names `netlist-spice-options` as its owner, and the list adds the missing `renumber off` and `scale off`.
16. **`simulation-netlist-preparation` ("Net name map") and `simulation-ui-and-crossprobe` ("Probing a layout net").** Both use the node-naming rule of `irsim-interface`, which is desktop-only (P-13). Both now say that the naming rule applies on iPadOS, even though the IRSIM interface itself is unavailable there.
17. **`SIMADV.md`.** Added `Resolution: fix` to Q-SIMADV-1, -2, -5, -6 and -7, each with what changed. The remaining parts of -2 and -5 are noted.

## Cross-group findings

- **`irsim-interface` (G5).** Probing and the simulation net-name map on every platform depend on Requirement "Hierarchical node names". G5 made `irsim-interface` desktop-only. That requirement should state that it applies on all platforms, or be moved to an always-available capability such as `netlist-spice-hierarchy`. Otherwise iPad probing depends on a desktop-only spec.
- **`netlist-spice-devices` / `extract-*`.** For sg13g2, `simulation-monte-carlo` requires `mm_ok=1` on every MOSFET, HBT, resistor and capacitor instance for mismatch. Layout-extracted netlists never write it, so extracted DUTs show no mismatch and only produce the warning (remaining part of Q-SIMADV-5).
- **`hefesto-magic-compat-mode`.** It covers only Magic quirks. LVS entries Q-LVS-7, Q-LVS-9, Q-LVS-20 and Q-LVS-24 say "replicate behind the compatibility switch", and Q-LVS-28 (which switch) is open. That capability will need a netgen counterpart, or a statement that `magic-compat` also governs netgen quirks.
- **`hefesto-architecture`.** The headless executable is named `hefesto-cli` only in a scenario. The requirement text should name it, because several command specs depend on it.

## Needs decision

1. **Q-LVS-28: `netgen-compat` or `magic-compat`.** This blocks the switch-gated behavior of Q-LVS-7, Q-LVS-9, Q-LVS-20 and Q-LVS-24.
2. **xschem quirks.** X-2 tiers apply to Magic. The SCHEM entries replicate xschem quirks (Q-SCHEM-12, -19, -20, -22, -26) with no switch, and fix others (Q-SCHEM-16). Decide whether X-2 (including a compatibility switch) applies to xschem, and to netgen, explicitly.
3. **Missing `Resolution:` lines.** No LVS or SCHEM entry has a `Resolution:` line (except Q-SCHEM-17), although X-2 tier 3 requires one. Example: Q-LVS-13 recommends fixing the JSON name for a log without an extension, but `lvs-reports` specifies netgen's `.json` name, which is correct until the entry is resolved. The same applies to Q-LVS-16.
4. **ngspice `.param` precedence (Q-SIMADV-3, -4, -9).** sky130 Monte Carlo mode `both`, the gf180 statistical overrides, and sweep overrides all assume that a later top-level `.param` overrides an earlier one. This needs a reference run before the specs are final.
5. **sg13g2 `mm_ok=1` for extracted DUTs** (remaining part of Q-SIMADV-5). See Cross-group findings.
6. **Q-SIMADV-11.** A `measured` waveform-retention mode as the default above 100 points (iPad storage).
7. **Q-SIM-11.** The engine spec resets the engine after a fault on every platform. The recommendation is to always replace the worker on desktop. Pick one before implementation.
8. **sky130 descriptor details (Q-SIM-8, Q-SIMADV-2).** Is `set ng_nomodcheck` still needed with the combined models? Should the desktop descriptor generator scan `libs.tech/combined` instead of `libs.tech/ngspice`?
9. **gf180 compatibility mode (Q-SIMADV-4).** The PDK's `.spiceinit` uses `ngbehavior=hs`, and the bundled descriptor uses `hsa`.

## Terminology

- The specs that use `corner sweep` (the P-7 era) and `corner set` (P-19) now agree: `corner sweep` creates an unnamed user corner set.
- The run-set concept is written "run set" in prose and `runset` as a command option and file name (`runset.json`). This is intended. Point jobs are "point jobs", and Monte Carlo points are "samples".
- The headless executable is `hefesto-cli` everywhere. `hefesto --netlist` was fixed.
- The gf180 section variable is `<proc>` in `simulation-netlist-preparation` and `<mos>` in `simulation-corners`. The latter is the owner, and the table now defers to it. The former was not renamed, because it is a placeholder in a summary table.
- Spelling is mixed in the `simulation-*` specs: British (behaviour, initialisation, optimisation, sanitisation, appear in requirement titles) and American (behavior) elsewhere. It is not normalized, because requirement titles are referenced by name. A project-wide choice is needed.
- "LVS netlist mode" (the `schematic-netlisting` requirement name) and "LVS mode" are both used. They mean the same thing.
- The ngspice reference is the same commit `7aa47164` in `SIM.md` and `SIMADV.md`. `SIM.md` dates it by the ngspice-47 release (2026-08-11). `SIMADV.md` dates it by the date of the research (2026-11-05). This is not a conflict.
