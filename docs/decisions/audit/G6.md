# Audit G6: agent, hefesto product, plugin, reliability and tapeout specs

Scope: the 44 capabilities `agent-*`, `hefesto-*`, `plugin-*`, `reliability-*` and `tapeout-*`, checked against `docs/spec-conventions.md`, decisions P-1 to P-23 and X-1 to X-6, `docs/roadmap.md` and `docs/specs-index.md`. After the fixes, `openspec validate <cap> --type spec --strict` passes for all 44.

Already consistent (no change needed): no "Metal on macOS", no AppKit or Catalyst desktop shell, no "full feature parity on iPad", no "pending X-3" and no "pending" gesture table remain in this group. Rendering, architecture and input match P-3/P-11 (Vulkan on desktop, MoltenVK on macOS, Raven viewports, Metal and SwiftUI on iPad) and the X-5 gesture table.

## Fixed

1. **`hefesto-licensing`.** The coverage of third-party components was incomplete.
   - xschem added to the GPL sources and to the clean-room rule (P-12), with a review scenario. KLayout is now stated as run-only, never linked or bundled (P-18).
   - The attribution list now also covers:
     - the linked ngspice parts: KLU, numparam, OSDI and sparse
     - the OSDI compact-model licenses (Q-SIM-2)
     - the Zstandard decoder for PDK assets
     - Eigen or any other solver library, if one is chosen (Q-RELIABILITY-9)
   - Copyleft parts (LGPL, MPL) are tied to Q-SIM-1 and Q-RELIABILITY-9.
   - The fonts requirement now names Inter and JetBrains Mono (OFL-1.1, used by `hefesto-design-system`), Roboto and Roboto Mono (from Raven) and FreeSans.
   - The decision traces were wrong: P-7 on attribution and P-2 on fonts. They are now P-9/P-11 and P-9/P-23.
2. **`hefesto-ipad-feature-scope`.** Brought up to date with every capability family:
   - Scripting is now listed.
   - Advanced simulation is listed by capability, including `simulation-optimization-hooks`.
   - Plugins are listed as `plugin-*`, with the App Review caveat.
   - `plot-output` and `hefesto-product-operations` are now listed.
   - It contradicted `digital-flow-mixed-signal`/`-results` (and its own "Graceful handling" scenario) by making all of `digital-flow-*` desktop-only. Now only `digital-flow-run` and `digital-flow-block-import` are desktop-only. Placing and running LVS on imported blocks, and browsing results read-only, are available on iPad.
   - Traces now include P-17, P-19, P-20 and P-21.
3. **`agent-schematic-driven-layout`.**
   - Routing wrapped `router-channel`, which is desktop-only and arrives in M12, after the agent's M11. The agent is also required on iPad. Routing now wraps `router-maze`, `router-maze-iroute` and `wiring-tool`.
   - A schematic (via `schematic-netlisting`) is now accepted as input.
   - The simulation loops now go through `simulation-optimization-hooks`, which removes the overlap with that capability.
   - Q-AGENT-1's evidence in `open-questions/AGENT.md` was updated to match.
4. **`agent-architecture`.** The tool list named a nonexistent `simulate` command. It now names `sim`, `iroute`, `sim_evaluate` and `sim_describe`.
5. **`hefesto-diagnostics`.** It said script bindings raise errors on command failure by default, with an unnamed "compat flag" to restore Magic's behavior. Its own scenario (`load nonexistent -fail` raises) broke the PDK `catch` idiom. This contradicted `scripting-api` ("Command status and error signalling") and Q-SCRIPT-2. Now: Tcl follows `scripting-api` by default, and errors are raised only in an opt-in strict mode. There are two scenarios.
6. **`hefesto-files-and-pdks`.** It allowed iPad PDKs to be "imported from the Files app", which contradicts P-14 (the PDK manager is the only way). Now: the PDK manager only, by download or offline pack. In **`hefesto-scripting`**, the curated-pack scenario now imports an unsigned offline pack instead of a "PDK folder".
7. **`hefesto-platform-targets`.** It said "Objective-C++ only in the Apple platform shell layer", which predates P-11. Now: Swift in the iPadOS shell only, Objective-C++ only in Apple platform services, and the macOS desktop shell is C++20 on Raven.
8. **`hefesto-app-ux`.** The Raven/SwiftUI window requirement traced to P-2. It now traces to P-11 and P-23, and the accessibility requirement adds P-11.
9. **`tapeout-signoff-checklist`.**
   - It cited the resolved Q-TAPEOUT-1 as its decision. It now cites P-18, in the Purpose, the KLayout text and the trace.
   - **Decision taken:** EM/IR is sign-off-relevant as an *optional* item, as P-21 says and `reliability-em-check` already defines. It was added as item 17 to the default order, the Purpose and the related capabilities. `tapeout-fill-and-density` also gets a P-18 pointer.
10. **`hefesto-testing-strategy`.**
    - Fuzz targets added: xschem `.sch`/`.sym` files, PDK-manager and plugin manifests and archives, EM rule files, and digital-flow reports.
    - Golden references now include the pinned xschem commit.
    - The iPadOS simulator is now in the determinism matrix only from the iPad milestone, matching `hefesto-build-and-distribution`.
11. **`hefesto-product-operations`.** The iPad memory requirement was blank. It is now "min 4 GB (A14), recommended 8 GB", consistent with the 3 GB resident bound of `hefesto-performance` and the 1.5 GiB IR budget.
12. **`hefesto-3d-visualization`.** Now points to `reliability-visualization` as the owner of the EM/IR datasets (overlap).
13. **Orphaned open questions now cited:**
    - Q-AGENT-1 to Q-AGENT-6 in the agent specs (none were cited before)
    - Q-PLUGIN-6 and Q-PLUGIN-8 in `plugin-api`, Q-PLUGIN-7 in `plugin-packaging-and-distribution`
    - Q-RELIABILITY-12 in `reliability-em-rules`
    - Q-TAPEOUT-16 in `tapeout-fill-and-density`, Q-TAPEOUT-17 in `hefesto-pdk-manager`
14. **Spelling.** Normalized to US spelling ("optimization", "color") in the edited text.

## Cross-group findings

- **`docs/roadmap.md`**
  - M5 schedules a "KLayout sign-off decision (Q-TAPEOUT-1)", and M13 says "follows decision Q-TAPEOUT-1". Both are stale: P-18 decided it. The de-risking table row should be removed or marked done.
  - The golden-capture pins list Magic, netgen and ngspice, but not xschem, which M8's exit criterion needs.
- **`docs/specs-index.md`.** Requirement and scenario counts are now stale for `hefesto-licensing`, `hefesto-diagnostics`, `hefesto-ipad-feature-scope` (purpose text) and the others edited above. Regenerate the index.
- **`docs/decisions/product.md` P-9.** It lists "bundled permissive components: Magic, Tcl, ngspice, zlib". ngspice is not wholly permissive (LGPL KLU/numparam, MPL OSDI). The list also omits Raven, MoltenVK, fonts and zstd. P-21 says "its own sparse linear solver", while `reliability-ir-drop` allows a permissive library (Q-RELIABILITY-9 recommends Eigen).
- **`simulation-engine-embedding`.** It says "pending Q-SIM-1". It is consistent with licensing, but Q-SIM-1 needs a decision before M14 (roadmap M9 de-risking).
- **`scripting-api`.** It says "reproduce this ok-status convention in compatibility mode" without naming the switch. Is it `magic-compat` or a separate strict-mode setting? `hefesto-diagnostics` now assumes ok-status by default and an opt-in strict mode.
- **`reliability-em-check` and `tapeout-signoff-checklist`.**
  - The checklist marks results stale on the GDS SHA-256. EM/IR runs are keyed on the cell modification stamp. The rule mapping a cell-keyed run onto a GDS-keyed checklist input is unstated.
  - The EM item uses "unless the program profile says otherwise". No built-in profile in `tapeout-shuttle-packages` sets it.
- **`ui-*` and `reliability-visualization`.** They say "error color"; `hefesto-design-system` names the token `danger` (status shape "■ error").
- **Open-question Resolution lines.** `hefesto-magic-compat-mode` requires a `Resolution:` line on every entry. AGENT, PLUGIN, RELIABILITY and most TAPEOUT entries have none, so every requirement citing them is provisional.
- **Conventions.** Tapeout and PDK-manager requirements trace to third-party tools (`tt ref:`, `mpw_precheck ref:`, `ciel ref:`, `IHP ref:`, `librelane ref:`) instead of `Magic ref`/`Hefesto decision`. That is reasonable, but `docs/spec-conventions.md` §2.3 does not allow it. 31 requirements trace only to such tools. Extend the convention to `<tool> ref:` with a pinned commit in the Purpose.

## Needs decision

1. **macOS x86_64 in CI.** P-2 supports macOS x86_64, and `simulation-analyses-and-results` lists `macos-x86_64`. But `hefesto-build-and-distribution` CI, the `hefesto-testing-strategy` determinism matrix and the roadmap exit criteria cover only macOS arm64. Either add x86_64 to CI or drop it from P-2.
2. **Unnamed dependencies with licensing impact.** These need a choice and a licensing entry:
   - SHA-256 and Ed25519 (PDK catalog, plugin signatures)
   - HTTPS client (PDK manager, plugin `http_request`, agent providers, updates)
   - Zstandard
   - JSON
   - glTF writing

   Platform crypto and networking on Apple and a permissive library on Linux would satisfy `hefesto-licensing`.
3. **Q-RELIABILITY-9 vs P-21 wording.** Own solver or Eigen (MPL-2.0)? Update P-21 to match.
4. **Script error convention (Q-SCRIPT-2).** Confirm the default (Magic ok-status) and the name and scope of the strict mode: per script, per plugin or per project. Script plugins (`plugin-api`) currently get Tcl errors on `HF_E_PERMISSION`, which is consistent with the strict style for the plugin API only.
5. **Resolution values.** X-2 lists `fix | compat | n/a`, but `hefesto-magic-compat-mode` adds `platform`. Amend X-2, or drop `platform`.
6. **iPad minimum memory.** Confirm "A14 / 4 GB minimum" against the 3 GB resident bound for the reference full-chip layout. That bound is measured on an 8 GB M1 iPad Pro, so a 4 GB device may not be able to open that workload at all.

## Terminology

- **US spelling:** "optimization" and "color". Other groups use British spellings: "optimisation" in `simulation-optimization-hooks`, and "colour" in some `simulation-*`, `schematic-*`, `plot-output` and `view-3d` specs.
- **"Sign-off ready" (P-18, `hefesto-ipad-feature-scope`) and the checklist state `ready`:** same concept. Prefer "`ready`" in specs.
- **Provider names:** "on-prem" (agent, iPad scope) and "self-hosted OpenAI-compatible gateway" (P-10) are used interchangeably. Keep "on-prem (OpenAI-compatible)" in the specs.
- **"PDK store" and "PDK root":** the store is the abstraction (`hefesto-files-and-pdks`); the root is its on-disk ciel layout (`hefesto-pdk-manager`). They are used consistently.
- **"compat flag" and "compatibility mode":** use the `magic-compat` setting name, or name the strict-mode setting explicitly (see Needs decision 4).
