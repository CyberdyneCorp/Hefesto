# Audit G1: app, cell, display, layout, tech and ui specs

Scope: app-startup, cell-*, display-style-files, layout-* (except layout-paint-semantics), tech-*, ui-*.
After the fixes, every spec in the group passes `openspec validate <cap> --type spec --strict`. Mechanical checks covered every requirement in the group: Compatibility line, trace, scenario, Q-ID existence, capability names and quoted requirement names.

## Fixed

- **layout-geometry-model**
  - Fixed a dangling reference: "Non-Manhattan geometry" → "Non-Manhattan (split tile) geometry".
  - Removed Magic identifiers `SigInterruptPending`, `MAXCOMMANDS` and `LOWCOMMANDS` from requirement text (the last two were in layout-undo). Reason: convention 2.2.
  - Replaced vague references (`cell-*`, `tech-*`) with the named capabilities.
- **app-startup**
  - "Default technology selection" now defers to `tech-loading-and-scaling` "Startup technology selection", which owns the algorithm.
  - Corrected step 1: a `-T` technology that failed to load is retried after the startup scripts, and the cell argument is not consulted. Evidence: utils/main.c:872-884, 1138-1150. The old text contradicted tech-loading-and-scaling.
  - "Crash recovery at startup" now refers to `cell-io-safety` "Crash recovery" instead of restating the candidate scan, and links `hefesto-files-and-pdks`.
  - In the Purpose, "the technology capability" and "the database capability" are now named (`tech-loading-and-scaling`, `cell-io-safety`).
- **cell-io-safety**
  - Crash backup policy said the periodic default is 10 min. The effective default is 1 min, because the tool setup sets 60000 ms before `crashbackups start` (tools.tcl:584-585, Q-SCRIPT-18). This contradicted `ui-gui-managers` "Crash backup timer". The text now cites that requirement as the owner of `crashbackups`.
  - Backup and archive cell order: Magic uses hash order. Hefesto now uses the deterministic name order required by X-1 (Q-CELL-28).
- **cell-library-resolution** ("Automatic technology discovery") — completed the requirement as the owner of the discovery behavior. Evidence: DBio.c:597-750.
  - A technology is still loaded by name when no directory is found.
  - The load skips the pre-check.
  - `tech load` hooks run on success.
  - The read fails if the technology still differs.
- **tech-loading-and-scaling**
  - "Automatic load from a cell's technology" duplicated cell-library-resolution. It is now reduced to the load semantics, without the pre-check, plus a reference to the owner.
  - The cell-scale route now cites `cell-file-format` "Coordinate scaling on read".
- **cell-file-format**
  - Writer elements: Magic's hash order is replaced by sorting by name with golden canonicalization (X-1 decided; Q-CELL-11).
  - Natural ordering: Hefesto now uses one total order on every platform (X-1; tie rule per Q-CELL-12).
  - Plane enumeration order now defers to `layout-geometry-model` "Tile enumeration order".
  - The scalegrid and grid-limit text now references `tech-loading-and-scaling`.
  - "compatibility mode" → "property compat mode" (terminology).
- **layout-properties**
  - Renamed requirement "Compatibility (compat) mode" → "Property compat mode".
  - Stated that this flag is unrelated to the `magic-compat` setting.
  - Named the referenced capabilities (`cell-file-format`, `cmd-labels-properties`).
- **layout-connectivity** ("Connect table")
  - Removed a false rule: "a contact connects to its residues and their connections" is not added automatically in Magic. Only stacked types get automatic connections (DBtech.c:383-405).
  - The requirement is now a summary that defers to `tech-compose-and-connect`.
  - The scenario now states the `connect` lines it relies on.
- **display-style-files**
  - Stipple orientation now follows Magic's OpenGL driver (X-5 decided). Before, the X11 orientation was normative. The scenario is updated.
  - The default dstyle class is `OpenGL`, with the others selectable (X-5, Q-UI-8).
  - "Style loading triggered by styletype" duplicated `tech-styles-section`, with conflicts:
    - exact vs behavioral;

  - The Purpose now names `tech-styles-section`.
- **tech-styles-section** — "the display capabilities" now names `ui-windows-and-views` and `hefesto-rendering`.
- **ui-tools-and-input**

  - `see`, `crosshair`, `findbox` and `feedback` are owned by ui-windows-and-views and ui-feedback-and-highlights, according to their Purposes. Suggest reducing them to references.

- **cmd-coordinates-and-units**
  - `grid multiple` "affects display": Magic never reads the value (grClip.c:52, Q-UI-21).
  - The "Scalegrid command" duplicates `tech-loading-and-scaling` "scalegrid command" (the content is consistent). Suggest a reference.
- **cmd-hierarchy** "Archive command" and "Crash backup command" have these errors:
  - `archive write` writes all available cells except internal, not-found and read-only ones, not just "modified cells". DBio.c:6463 has the read-only exclusion.
  - The `read` and `readref` semantics are misstated.
  - The format owner is `cell-io-safety`, not `cell-file-format`.
  - `crash recover` picks the newest status-change time, not "the first found".

- **agent-safety-and-approval** "Accept is a single undo step" conflicts with `layout-undo` "Non-recorded operations". Property changes, cell create, rename and delete, and flatten are not undoable, so one `undo` cannot restore the state of a multi-cell proposal. **simulation-command** relies on `layout-undo` for testbench edits, which layout-undo does not record. A native extension to layout-undo is needed (see Needs decision).

  - These entries are resolved by decided items and need a `Resolution:` line: Q-UI-6, Q-UI-8 and Q-UI-22 (X-5); Q-CELL-11, Q-CELL-12 and Q-CELL-28 (X-1).

## Needs decision

1. **Owner of the `undo`/`redo` command surface.** This covers `undo n`, `print`, `enable` and `disable`. No spec defines it. Candidates: `layout-undo` or `ui-command-dispatch`.
2. **Reference build.** Because of X-3, Hefesto always embeds Tcl. Should Magic's *Tcl-build* behavior be normative wherever builds differ? Affected areas:
   - the `tool` command;
   - `echo`, `send` and `source` registration;
   - the startup-file rules;
   - `$VAR` sources in cell-library-resolution, where the spec says "without Tcl, step 1 is skipped".

   Recommendation: declare the Tcl build normative in spec-conventions.
3. **X-1 for backup and archive order.** I applied X-1 to backup and archive cell order (Q-CELL-28 is not in X-1's ref list). Please confirm. The exact tie-break of the natural comparator (Q-CELL-12) is still open.
4. **Agent acceptance as one undo step (P-10).** Either extend layout-undo to record properties and cell lifecycle inside agent and simulation steps, or narrow the P-10 promise.
5. **Desktop crash backups.** Do Linux and macOS keep Magic's `$TMPDIR/MAG<pid>.*` files, for interoperability, or use the app-private autosave? The current recommendations disagree: Q-UI-31 says app-private everywhere, while Q-CELL-30 keeps reading `MAG*`.

## Terminology

- `property compat` flag / "compatibility mode" / `magic-compat` / substrate "compatibility mode" (ext-flattening) / ngspice "compatibility mode" → use **property compat mode**, the **`magic-compat` setting**, and **substrate compatibility mode**. Never use a bare "compat mode".
- Lambda scale notation has three forms:
  - cell-file-format: λ ratio `(L0, L1)`;
  - cmd-coordinates-and-units: `Λ = L1/L0`;
  - tech-loading-and-scaling: "I internal units = L lambda".

  Recommend one notation, for example **"internal units per lambda I/L"**, with a mapping note.
- Search paths: "Path", "search path", "cell library path", "library path", "system library path" and "SysLibPath" → use **cell search path** and **system search path**.
- Path opening: the rules are restated three times, consistently, in tech-loading-and-scaling "File search rules", display-style-files "Style file search path" and app-startup. Recommend a single owner.
- "read-only" / "not editable" / "no-edit" → **read-only**.
- "crash backup" (Magic) vs "autosave" (hefesto-files-and-pdks) → keep **crash backup** for the Magic-compatible file and **autosave** for the platform service, and say so explicitly.
- "use" / "instance" / "cell use" → **instance**, with "use" only for the `.mag` keyword.
- Cross-reference style is mixed: `(see Requirement: X)`, `(see "X")` and `requirement "X"` → use **capability `c`, requirement "X"**.
- layout-geometry-model still uses `INFINITY` and `MINFINITY`, which are Magic macro names. Suggest the names "plane infinity" and "plane minus infinity".
