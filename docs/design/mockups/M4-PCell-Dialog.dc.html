M4 · Scripting and PDK integration

Place device and the PCell parameter dialog

Place device on the tool rail (disabled since M2) now opens a list of the PDK's device-menu items. The parameter dialog renders pcell::DialogModel, which the device's <ns>::<device>_dialog procedure fills through the builder API (add_entry, add_checkbox, add_selectlist, add_message, add_dependency). Its structure is Magic's .params window: mode, device, library, cell name, instance, parameters, and the buttons. Create issues magic::gencell <lib>::<device> {} k v …; Apply issues the same command with the instance name.

Notes for SHELL

  • 1Place device is a rail button, not a tool mode: it opens a popover listing the PDK's device-menu items (the same MenuModel / ToolkitMenus entries as Devices 1 and 2, grouped by menu, with a filter). It is disabled with the tooltip "No PDK device scripts" when the project has none, or the scripts were declined.
  • 2Choosing an item issues its command (magic::gencell sky130::sky130_fd_pr__nfet_01v8). Items that draw directly (*_draw) paint at the box and open no dialog. The last device used is listed last with its ^P binding.
  • 3Header: the device mode (New device:/Edit device:), device type, library, cell name or (default), and the editable Instance entry. The chip says whether a native generator for this exact PDK version is used, or Tcl.
  • 4Parameter rows in the builder's grid order: entries are 150 px mono inputs, checkboxes are 16 px, and select lists are menus. add_message rows are read-only text in the warning color (the PDK's brown). The body scrolls and the header and buttons stay fixed. Rows are a virtual Raven grid, so the dialog builds quickly for devices with 40 rows.
  • 5Buttons: Create (keeps the dialog open, now in edit mode for the new instance) and Create and Close (default, Return) for a new device; Apply and Okay for an existing one; Reset (defaults for this type) and Close always. Create with the default instance name issues magic::gencell_create <type> <lib> {k v …}, a named one magic::gencell <lib>::<type> <inst> k v …. The dialog is a non-modal window above the layout window (always on top until Raven has owned utility windows; accepted 2026-11-11). Selecting another generated instance with select cell switches it to that instance.
  • 6Edit state from the selection: header values come from the cell's library, gencell and parameters properties; for fixed devices the framework adds pitchx/pitchy.
  • 7stderr lines of _check become a ▲ banner (shape and text, never color alone); the corrected field gets a warning outline with what was typed below it. The banner clears on the next edit.
  • 8Dependency updates are announced politely ("Value updated to 2.94k").
  • 9When gencell fails and no dialog is involved (from a script, the console or Ctrl-P), the error goes to the Console and the status bar, and no dialog opens.
