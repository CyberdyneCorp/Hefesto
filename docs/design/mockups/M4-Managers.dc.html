M4 · Scripting and PDK integration

Cell, library and technology managers; text helper; layer toolbar

Magic's Tk managers become Hefesto panels and dialogs that render the view models of gui:: (CellManagerModel, LibraryManagerModel, TechManagerModel, TextHelperModel, ToolbarModel). Every button issues the command that Magic's manager issues, so it is logged and replayable. The Options menu shows and hides them, and so do the commands cellmanager, libmanager, techmanager, make_texthelper and maketoolbar. The DRC manager is the M3 DRC panel.

Notes for SHELL

  • 1Cell manager: the M1 Hierarchy panel, renamed Cells, gains Magic's columns (cell, first instance name) and buttons. Load = load <def> (then clearstack), Edit = select the instance path, then expand; edit, Expand = expand toggle, Place = getcell <def>, Zoom = findbox zoom (view for a top cell). Target picks the window (Opts(target)). A select highlights the selected instance's row.
  • 2Library manager: one node per path search then path cell directory, with path variables shown unexpanded ($PDKPATH). Only the first directory is open. It lists *.mag files whose header says magic / tech <name>, filtered to the current technology. Load = load, Place = getcell <cell> child 0 0, Pick = pick tool plus place and move. It refreshes after addpath, path, save and writeall. The tree is a virtual Raven tree (446 cells in sky130_fd_sc_hd).
  • 3Technology manager: name, version and description, microns per lambda, the internal units per lambda entries (editing them issues scalegrid), and the CIF in/out, extract and DRC style menus (cif istyle, cif ostyle, extract style, drc style). The technology menu lists tech load targets and the PDKs under the store root; choosing a PDK sources its rc file, which goes through consent (M4-Script-Consent).
  • 4Text helper: a non-modal utility window with Magic's fields. A 3×3 justification grid plus a center/default choice replaces Magic's menu. The command preview line shows what Apply or Okay will issue; with a label selected, the fields are read with setlabel and Apply issues setlabel per changed field. After a port is created, the port index advances to port last + 1.
  • 5Layer toolbar = the layer palette in toolbar order: errors labels subcell first (unless hide-special), then tech layer *, or the unlocked layers with Toolbar Hide Locked. Magic's row bindings map onto the M2 palette: click = see, middle = paint, Shift-middle = erase, and the keys p/e/s/S/l/u.
  • 6Reorder dialog: rows drag or move with Move layer; Group selected puts several layers on one toolbar row; Delete layer removes one from the preset. Confirm applies the order in memory; Load reads a preset from <tech>_toolbars.tcl through the host file API (as data, never evaluated, Q-SCRIPT-11/28); Save rewrites its set current_toolbar {…} line. Skipped lines of that file are ▲ Diagnostics rows.
