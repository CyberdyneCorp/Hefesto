# Proposal: M4 Scripting and PDK integration

## Why

M3 made Hefesto check the layout, but no real PDK flow runs yet. There is no Tcl interpreter: `cmd::run_script` is a placeholder reader without `$`/`[ ]` substitution, `set`, `proc`, `if` or `expr`. A PDK `.magicrc` contributes only its literal `set NAME value` lines ("its script commands run once the Tcl binding exists (M4)"), the implicit `<tech>.magicrc` of technology auto-discovery is skipped, `tag`, `gencell`, `readspice` and `cif` are not commands, the tool rail's "Place device" is disabled ("arrives in M4"), and nothing asks before a PDK script would run. M4 (docs/roadmap.md, "M4") runs the sky130, gf180mcu and IHP sg13g2 startup files, device generators and menus unchanged in an embedded, sandboxed Tcl (X-3), adds generator dialogs and native C++ generators validated against the Tcl ones, `readspice`, the auxiliary tools and the GUI managers, and closes the desktop items carried from M2. The result is the Desktop Alpha: open, edit, DRC-check and place PCells in real PDK designs on Linux and macOS.

The 34 open questions that blocked M4 are resolved (commit "Resolve the 34 open questions blocking M4", with the user's choices for Q-SCRIPT-9, 11, 34, 41, 42 and 46) and the M4 specs are aligned with them (commit "Align the M4 specs with the approved decisions"); `scripts/check_milestone_readiness.py --milestone M4` reports ready. Five audit decisions that also block M4 are not settled by those answers (D-29, D-31, D-33, D-34, D-36); design.md "Open Questions" lists them with the default each workstream builds against until the user decides.

## What Changes

- **PDK pins first (PDK).** Q-SCRIPT-9 (a): `scripts/fetch_pdk.py` moves from open_pdks `0fe599b2`/IHP `ddb601a4` to the spec pins, open_pdks `c6df28c1` (ciel release `sky130-`/`gf180mcu-5740c4a8…`, whose Magic files are those of `c6df28c1`; design D15) and IHP-Open-PDK `5e6d592e` (ciel `ihp-sg13g2-5e6d592e…`). The M1–M3 PDK-based unit and golden tests are re-run on the new pins before any M4 code depends on them; a changed result is fixed or recorded through an approved decision. One smoke case keeps the older rc generation covered.
- **Embedded sandboxed Tcl (TCL).** Tcl 8.6, built from source as a static library without Tk, one interpreter per open project (Q-SCRIPT-41). The sandbox (X-3, `hefesto-security`) removes process execution, sockets and native `load`, and confines every file access to granted roots through a Tcl virtual-filesystem layer; denied operations name the script and line.
- **Command binding (BINDING).** `scripting-api`: every command in `magic::` with Magic's registration, global import, collision renames and unknown handler; quiet dispatch; `tag` and the single-pass substitution of Q-SCRIPT-3; window-directed commands; output through `puts` with literal `$` (Q-SCRIPT-4); prompts; the engine-read variables, including path-variable caching per magic-compat (Q-SCRIPT-5); the result formats (`port last` Q-SCRIPT-6, `cif scale` Q-SCRIPT-7, `drc listall why` in Magic's hash order Q-SCRIPT-8); the tab-terminated keyword rule (Q-SCRIPT-14); `magic::drcstate` from the M3 DRC events.
- **PDK startup, scripts and consent (PDKINT).** `scripting-pdk-integration` and `hefesto-security`: the Magic startup sequence and command line (Q-SCRIPT-33, 37), startup files as Tcl, the three PDK rc and device-script contracts, the helpers left to the PDKs with the cross-PDK warning, the generator command surface (the missing `cif`, `tag`, `ext2spice scale` forms), the inventory trace, technology auto-discovery with its `<tech>.magicrc` behind the consent prompt, trust per PDK version, PDK-relative paths, the interception of the PDK menu widget calls (Q-SCRIPT-42/34, D-32) and the curated-pack refusal (Q-SCRIPT-46, D-30).
- **PCells (PCELL).** `pcell-toolkit`: the gencell framework as native C++ behind Magic's `magic::` procedure names (dispatch, naming hash Q-SCRIPT-22, normalization Q-SCRIPT-21, properties, create/change Q-SCRIPT-23, 24, 29, dependencies Q-SCRIPT-25, the dialog builder API as a dialog model, menu hooks, SPICE seeding), and native C++ generators for the MOSFET families and fixed devices of the three PDKs, validated against the Tcl generators over a parameter sweep in CI.
- **readspice and auxiliary tools (TOOLS).** `readspice` with the compat continuation spacing and the fixed message (Q-SCRIPT-32, 19); `scripting-auxiliary-tools` (socket server absent, BSI helpers and legacy toolkit not loaded, reference-library stripper, console integration, launchers, tech builder); `mazeroute` is deferred to M10 with `router-maze-iroute` (Q-SCRIPT-30).
- **GUI managers (GUIMGR).** `ui-gui-managers` as core view models and commands: wrapper hook points (Q-SCRIPT-13), menu model (Q-SCRIPT-36), technology manager, layer toolbar and presets read as data (Q-SCRIPT-11, 28), cell and library managers (Q-SCRIPT-27), DRC manager and `drc_save_report`/`drc_load_report` (Q-SCRIPT-26), text helper (Q-SCRIPT-31), file prompts, crash-backup timer, tool modes.
- **Desktop (DESIGN, SHELL, CARRY).** Boards first for the new screens (PCell dialog and Place device, script consent, PDK menus and the menu bar, cell/library/technology managers, text helper, layer toolbar and reorder, script console), then the screens; and the items carried from M2 (floating panels and drag-to-dock, saved panel layout, key-binding sheet, label popover, `unmeasure` on Escape, Paint tool state, named undo steps and press-and-hold history, per-area minimap, pixel-width highlight outline, wiring HUD and inspector, crash-dialog capture, VoiceOver press, and the Raven confirmation checks).
- **Golden and exit checks (GOLDEN, INTEGRATION).** The 89 SCRIPT golden cases plus SCRIPT-PDK-18 (older rc smoke), the cases of earlier areas that waited for Tcl, re-capture of the PDK-based cases on the new pins, the Desktop Alpha end-to-end check on Linux and macOS, fuzz targets for the new readers, and the docs.

### Non-goals

- The iPad app and its shell (M14). M4 keeps the core platform-neutral (sandbox, interception and curated-pack logic are core code with unit tests) and builds Tcl for the `ipados` preset, but no iPadOS UI.
- `mazeroute` and its maze helper window (Q-SCRIPT-30, M10 with `router-maze-iroute`); a seed-pinning setting (Q-SCRIPT-44, with Q-MASK-211 in M5); GDS/CIF reading and writing behind the generators' utility scripts (M5); extraction behind `ext2spice scale` (only the setting is stored, M7).
- Native generators for every PDK device. M4 delivers the MOSFET families and fixed devices (design D10); the other devices run their Tcl generators, which `hefesto-scripting` allows as the fallback.
- A Tk-compatible widget layer (Q-SCRIPT-42 option a, rejected).

## Capabilities

### New Capabilities

None.

### Modified Capabilities

None. M4 implements the existing requirements of the 8 capabilities listed in docs/roadmap.md ("M4"): `hefesto-scripting`, `scripting-api`, `scripting-pdk-integration`, `pcell-toolkit`, `readspice`, `scripting-auxiliary-tools`, `ui-gui-managers`, `hefesto-security` (92 requirements, 58 of them exact or behavioral; `mazeroute`'s one moves to M10). Every open question cited by these specs is resolved and the specs were aligned in the preceding commit. The change therefore sets `skip_specs: true`, following the M0–M3 precedent (m0-foundations design D10). A workstream that finds a requirement that must change raises it as an open item; INTEGRATION then edits the living spec in this change's branch.

## Impact

- **New code:** `src/core/{include/hefesto,src}/script/{tcl,binding,pdk}/`, `src/core/{include/hefesto,src}/pcell/{framework,native}/`, `src/core/{include/hefesto,src}/tools/` (readspice, auxiliary), `src/core/{include/hefesto,src}/gui/` (manager view models); `src/shell/desktop/` (menu bar, PCell dialog, consent, managers, console, carried M2 items); `tests/unit/{script,pcell,tools,gui}/`; `tests/fuzz/{fuzz_tcl_sandbox,fuzz_toolbar_presets,fuzz_readspice}.cpp`.
- **Shared changes:** `cmd::run_script` (the placeholder reader) is replaced by evaluation in the project interpreter and removed at M4 exit (design D3); `EditorState` gains the project interpreter; `app/startup` runs startup files through Tcl; `cell::IoSession::discover_technology` runs `<tech>.magicrc` after consent; the keyword lookup gains the magic-compat OFF whitespace rule; `drc listall why` switches to Magic's hash order and the golden comparator's sort for it is removed; `port last` and path-variable caching become mode-dependent.
- **Dependencies:** Tcl 8.6.16 (BSD-style license), fetched by URL with a pinned SHA-256 through FetchContent and built as a static library; `THIRD_PARTY_NOTICES.md` moves Tcl from "to be added" to the component list.
- **Data:** the PDK sets move to open_pdks `c6df28c1` (ciel `5740c4a8…`) and IHP `5e6d592e`; the sky130 subset gains `sky130A/libs.tech/magic` device scripts (already in the subset) and the gf180mcu and ihp subsets stay as in M3; never committed.
- **Golden cases:** SCRIPT (89 + SCRIPT-PDK-18), MODEL-G-055, CELL-PR-03, CELL-PW-05, CELL-PR-12 (per D-33), UI-G-009/013/049 (deferred to M4), DRC-PDK-3 with the real IHP `cap_cmomf` generator; every PDK-based case re-captured on the new pins; deviations for Q-SCRIPT-3 (Magic hangs), Q-SCRIPT-4 and Q-SCRIPT-32 (message).
- **Docs:** `docs/design/m4-ui-conformance.md`, new boards, diagnostic code documents (`SCRIPT-`, `PCELL-`, `TOOLS-`, `GUI-`), building (Tcl, PDK pins), contributing, security notes, roadmap status, the App Review inquiry record.
